# Saved offline audio: method, evidence, and limits

The saved-version workflow is real, but **soundboard-grade restoration is not established**. The final Android candidate abstained on **all 24 full recordings** in the locked study. A separate six-recording early-tape extension found one modest bass correction, so **29 of 30 full recordings remained unchanged**. Neither that correction nor the narrower known-defect experiments meet the requested high-quality restoration goal. No human listening ratings have been collected; the listening package is an evaluation deliverable, not a claim that listeners preferred the output.

The candidate is conservative, track-adaptive mastering. It does not recover a clean source, separate the band from the crowd, repair clipping, or generate missing musical detail. When no clear correction qualifies, the app reports that outcome and retains the original without storing a duplicate WAV. The research harness still renders unchanged copies to validate exact duration and sample preservation.

## Corpus and experimental separation

`manifest.json` locks 24 full audience recordings spanning 1992–2025 (four decades), different venues, microphone lineages, quiet and dense music, prior mastering, dual-mono, and long jams. `acquisition.json` records complete-source hashes and download metadata. The compressed source collection is approximately 396 MB and 3.674 hours. Full source audio and rendered files stay outside the repository in task scratch storage.

Sixteen recordings are development material. Eight entirely new show dates were reserved before waveform analysis. The previous investigation's twelve recordings cannot be called an untouched holdout, so all twelve belong to development. The evaluation harness snapshots the exact Java source it compiles. It requires a frozen implementation and measurement-protocol fingerprint before opening the eight holdout recordings. This is a small convenience sample, not a statistically representative estimate of the Phish archive.

The full-track evaluation includes duration and content consistency, sample peaks, a 4× oversampled peak estimate, FFmpeg's EBU loudness/true-peak meter, loudness range, crest factor, stereo correlation, side/mid energy, frequency-band coherence, envelope correlation, onset-flux correlation, and the quieter fifth of the track. Quiet passages are **not semantic crowd labels**. The original report retains raw measurements, including the poorly conditioned side/mid ratio of essentially dual-mono sources; width-change checks are inapplicable when both versions' side energy is below −60 dB relative to mid.

## Candidate implemented in the app

The renderer makes one complete analysis pass over the decoded source to derive an immutable profile. If a correction qualifies, a second pass writes a separate PCM WAV; otherwise the app reports the unchanged result without storing a duplicate. Decoder chunks can have arbitrary whole-frame lengths. The processing core uses bounded memory and has no network or model dependencies. Original files are untouched. Decoder/render cancellation and atomic publication are responsibilities of the surrounding background worker.

Analysis uses approximately 46 ms sine windows: 1,024 points at 22.05/24 kHz, 2,048 at 44.1/48 kHz, and 4,096 at 88.2/96 kHz. Scaling the FFT size avoids a different confidence decision caused merely by reduced frequency resolution at higher sample rates. Empty reference bands never count as evidence of a spectral valley. Near-silence does not set the profile, and short or spectrally sparse material causes abstention.

For each active analysis frame, the analyzer computes channel-linked energy density in 26 bands. Between 100 Hz and 1 kHz, a band's log-energy is compared with the log-frequency interpolation of the bands roughly one octave below and above it. Only the lower quartile of this excess is eligible: a proposed broad peak must persist in at least 75% of the analyzed windows. Excess above 3 dB is corrected at half strength, capped at 3 dB, and smoothed between bands. Corrections below 0.25 dB cause bit-exact abstention. These limits were chosen using development experiments; they are engineering guardrails, not validated perceptual thresholds.

Rendering uses a sine-window weighted overlap/add transform with 75% overlap, explicit normalization, leading-delay removal and end flushing. It preserves exact frame count. Static broad attenuation is supplemented by up to 1.5 dB of additional adaptive attenuation only in bands already supported by the persistent-peak profile. This attenuation requires excess energy above the full-track 80th percentile plus 1.5 dB. Positive spectral flux protects abrupt onsets; high spectral flatness protects broadband ambience; quiet frames are protected. Attenuation engages slowly and releases quickly. There is no noise gate, blanket noise-floor subtraction, stereo widening or per-channel automatic gain.

Each time-frequency bin uses the same real-valued gain in both channels. This preserves the interchannel ratio and phase within that transform representation; it does **not** guarantee unchanged broadband correlation or perceived width, which are measured separately. A single fixed gain reserves headroom on hot sources. Any new integer clipping rejects publication instead of silently accepting a distorted result. Existing clipping is not repaired.

This approach can modestly reduce persistent low-mid buildup. It cannot determine whether every broad peak came from the room, an instrument, the taper's mastering, or an artistic choice. The Original/Enhanced choice therefore remains explicit, with original playback immediately available.

## Full-track outcome

The frozen final candidate processed **24 complete recordings totaling 3.67444 hours**: 16 development recordings and eight previously untouched holdouts. **All 24 abstained**. Every rendered PCM stream was verified bit-exact against the decoded original, with identical frame counts. All 24 passed the numerical preservation checks, but unchanged output trivially preserves those properties; these results provide no evidence of an improved recording.

The local evaluation package contains 24 full-length WAVs and 96 blinded comparison pairs (four passages per recording). In this candidate's final package the compared samples are identical. That fact must be disclosed, not hidden behind an “enhanced” label or a successful-test count. Earlier mean-based development renders and separate dereverberation experiments are retained as research evidence of actual changes and their limitations.

The revised confidence rule was frozen before the eight holdouts were analyzed. A later readability-only Java formatting change is linked to the development snapshot by `evidence/formatting-equivalence.json`, which verifies identical JVM instructions and constants for all four relevant classes. No algorithm parameters were retuned using holdout results.

### Exploratory early-tape extension

After the locked study, six additional complete audience recordings from 1989–1991 were selected using documented cassette-generation, hiss, distortion, obstruction, distant-microphone, wow/flutter and dropout problems. This **54.8-minute exploratory extension is not another untouched holdout**. It did not change the frozen processor or its confidence thresholds. Across both studies there are 30 full source recordings, approximately 4.588 hours, spanning 1989–2025.

Five of these six again abstained bit-exactly. The 1990-04-29 *Walk Away* qualified for a 1.0 dB static reduction at 100 Hz, 0.5 dB shoulders at 80/125 Hz, and up to 0.562 dB additional dynamic attenuation. Its onset correlation was 0.999797, envelope correlation 0.998673, crest change −0.048 dB and side/mid change +0.346 dB. No new clipping occurred. The unnormalized output was 1.5 LU quieter; listening versions are loudness matched so this level difference cannot be mistaken for quality. All six passed the provisional preservation checks.

This is an actual, modest bass correction on one source, **not repair of that tape's documented phase obstruction**. The other documented defects remain unaddressed. `hard-case-manifest.json` records the selection provenance, `hard_cases.py` reproduces the extension, and `evidence/exploratory-hard-cases.json` preserves proposed versus actually applied corrections and full metrics. The separate local listening package contains 24 comparison pairs and all six full rendered files. Subjective ratings remain absent.

## Development iterations and known-reference tests

The initial estimator used mean spectral curvature. Its complete numerical evidence is retained in `evidence/controlled-mean-profile.json`. On 36 trials—four development passages, three broad bell frequencies (160/315/630 Hz), and three added gains (3/6/9 dB)—median reference-error improvement was only **0.343 dB**. Twenty-three trials improved by more than 0.1 dB, eight worsened by more than 0.1 dB, and the worst deterioration was **2.247 dB**. It could remove genuine coloration elsewhere while correcting a mild artificial defect. That version was rejected.

The persistent-peak confidence revision produced **zero worsened cases** in the same 36 development trials. Twelve improved by more than 0.1 dB; 21 abstained and returned identical PCM. Median improvement including abstention was **0 dB**, and the best was about **1.215 dB**. This is improved caution, not evidence of a dramatic restoration breakthrough. These trials influenced development and are not a held-out confirmatory test.

In these tests, the reference is the original audience recording *before* a known extra defect was introduced. It is not an independently recorded clean concert. Reconstruction error is evaluated after one global level alignment, so simply making audio quieter cannot count as improvement. `controlled_degradation.py` reproduces the tests through the exact Java renderer used by Android.

## Separate classical audition candidate

To obtain actual changed candidates beyond the conservative Android processor, `classical_probe.py` implements one additional, preregistered mastering experiment. Its reference is fitted from all sixteen **complete development recordings**: eight octave-band energy proportions are normalized within 20-second blocks, reduced to per-recording medians, then combined with equal recording weight into cohort medians and quartiles. **Each target profile in this six-passage experiment is estimated from its 20-second passage**, not from that target's entire recording. Neither this archive-derived reference nor its statistical spread establishes the desired artistic balance or a clean/soundboard target.

The tonal variant corrects only deviations outside the cohort interquartile interval expanded by 1.5 dB, at half strength, limited to ±2 dB and smoothed broadly over log frequency. Positive gain tapers to zero by 3.5 kHz and below 50 Hz. The second variant adds sustained-band, stereo-linked compression with ratio 1.25:1, a 65th-percentile threshold and at most 1 dB attenuation. Its 80 ms attack/400 ms release is overridden by explicit onset, broadband-rise and quiet-frame protection, which resets prior reduction. Both use the same real gain in the two channels. There is no noise gate, crowd deletion, source separation or generated content.

The source/reference/configuration/script hashes and unity-transform checks were frozen in `evidence/classical-preregistration.json` before any rendering. Four selected natural passages were completed before two reserved passages. The reserved recordings were excluded from reference fitting, but their originals had already been measured in the earlier study; they are not newly untouched recordings. No sweep or post-result adjustment occurred. The original Android processor and 24-track frozen protocol remain unchanged.

All twelve outputs differ from their originals and pass the existing provisional preservation bounds. The minimum onset correlation is 0.99838; maximum absolute crest and side/mid changes are 0.491 and 0.378 dB. Energy-weighted phase error measured from reconstructed, quantized PCM is at most 0.0181°. Large individual weak-bin phase deviations remain in the raw report; shared transform gains do not imply perfect every-bin output phase.

An independent, posthoc audit of the delivered FLACs (`classical_artifact_audit.py`, `evidence/classical-artifact-audit.json`) uses a separate Welch spectrum and measures actual output. After loudness matching, Reba gains about 1.6 dB around 1 kHz, while the reserved 1992 passage loses about 1.3 dB near 16 kHz. These changes **can alter desired instrument or ambience tone**, rather than fixing a defect. Reba's crest rises about 0.49 dB despite the gentle dynamics option; the processing is not evidence of universally improved dynamics. Phase deviations above 30° carry at most 1.53×10⁻⁷ of the measured cross-channel weight, but that numerical support does not prove inaudibility. No candidate was retuned after this audit.

The local `audio-classical-probe/RoboPhish-classical-audition.zip` is a 59.3 MB, self-contained audition package: four selected 20-second passages with randomized Original/tonal/tonal-plus-dynamics labels, plus two separately presented reserved passages. Unzip, open `index.html`, then select the extracted folder using the page's file picker. Ratings start empty and remain local; the answer key is separate. All eighteen FLACs have exact verified duration and alignment, safe common peaks, and decoded loudness spread below 0.000000012 LU. JavaScript syntax, file links and ZIP CRC passed. Browser playback itself remains unverified because the earlier browser-tool local-file request was denied; no alternate browser/server workaround was attempted.

This candidate is **research-only**, with no established listening preference or general full-track benefit, and is not the processor currently installed in the app. The immediate decision is whether listeners prefer any of these matched, actually changed passages while retaining musical identity and natural live atmosphere. Passing numerical guards is insufficient to promote it.

### One additional full-track classical validation

`classical_full_track.py` extends the unchanged candidate to a complete 2016-10-31 *It Ain't Easy*, a previously reserved recording excluded from the reference cohort. This is one additional exploratory validation, not a new sweep. Unlike the audition excerpts, **this target's tonal and dynamics profiles use the complete 210.733-second recording**. Two bounded-memory STFT passes accumulate full-track statistics and then reconstruct with continuous overlap/add and dynamics state. Before this run, the streaming implementation matched the frozen excerpt functions exactly for a natural Reba passage, 48 kHz boundary impulses/noise, and silence; unity error was at most 7.8×10⁻¹⁶.

The validation wrapper was frozen before processing the target. An initial preregistration is retained alongside its replacement: the only added requirements were explicit first/last-second and reconstructed-phase diagnostics, requested before the full render. Processing parameters and the cohort reference did not change. The source, both WAVs and frozen inputs were hash checked afterward. All 9,293,340 stereo PCM16 frames are present in both saved outputs.

**The complete-track profile requested no tonal correction.** The tonal-only file is bit-exact to the decoded original. The dynamics variant applies up to 0.999 dB attenuation during about 22.9% of frames, with protection active in about 71.5%. Both whole-track evaluations, all 22 variant/window evaluations and all four first/last-second evaluations pass the existing numerical bounds, with no undefined metrics. The final second is bit-exact in both versions. Across 20-second windows, minimum onset/envelope correlations are 0.998596/0.998485, maximum absolute side/mid change is 0.0462 dB, and maximum energy-weighted reconstructed phase error is 0.07794°.

Profiling took 1.36 seconds and reconstructing both versions took 3.26 seconds on this local desktop run; these figures **exclude peak/headroom conversion and measurement**, and are not phone benchmarks. Measured process peak RSS was 414.6 MB, above the 300 MB design aspiration but below a multi-gigabyte full-transform allocation. `evidence/classical-full-track-results.json`, the preregistration/equivalence records and `classical-full-track-artifact-validation.json` retain the complete result.

This supports full-length reconstruction and restrained dynamics continuity on one recording. It supplies **no full-track listening evidence for nonzero tonal correction**. Short-passage spectral differences can reflect the music being played as well as recording coloration; a pleasing excerpt change must not automatically be treated as a justified recording-wide correction. The small audition package remains unchanged, and neither classical variant has been promoted into the app.

## Independent dereverberation and model review

| Candidate | Evidence and decision |
|---|---|
| NARA-WPE | The MIT-licensed NumPy implementation is a feasible local CPU baseline. It is designed for speech dereverberation, so music/crowd preservation requires separate evidence. Four development excerpts were tested with six taps, three-frame prediction delay and two iterations. Full WPE worsened reconstruction error in three of four known added-reverb tests (−3.25, −2.91, +1.04, −0.80 dB), and altered spatial/dynamic measurements. A 25% blend gave only +0.14 to +0.59 dB. A shared attenuation mask bounded to 1.5 dB gave +0.06 to +0.35 dB. None ships. See `evidence/wpe-comparison.json` and `model_comparison.py`. [Official implementation](https://github.com/fgnt/nara_wpe). |
| Apollo | **Actually evaluated locally**, using pinned official code and checkpoint. The 66.5 MB checkpoint contains 16.58 million tensor elements. Its documented task is music codec-artifact restoration, not room dereverberation or crowd separation. Eight short local MPS passes took about 3.77× audio duration. Known extra-64 kbps tests showed spectral-error reductions, with a waveform-error tradeoff detailed below. No code or weights are bundled into Android. Both use CC BY-SA 4.0, which carries share-alike conditions rather than attribution alone. ### Apollo development experiment

`neural_probe.py` verifies the official source revision and checkpoint SHA-256, then uses `torch.load(weights_only=True)` with inert placeholders for unused configuration metadata. Unknown checkpoint globals are rejected; the upstream unsafe pickle-loading path is not executed. Inference is local. Four development passages were tested both as supplied by the archive and after a controlled additional 64 kbps MP3 round trip. Each has a 10-second measurement region inside 14 seconds of real context. No holdout informed this development experiment.

For the four known codec defects, the raw model reduced mean multi-resolution spectral-convergence error by **1.67%**, and a 25% residual blend by **3.21%**. Mean high-band (6–18 kHz) log-magnitude error fell **30.95%** raw and **14.97%** blended. All four trials improved these spectral measures. Raw waveform reference SNR nevertheless worsened by **0.24–0.56 dB**, while the 25% blend improved it by **0.125–0.230 dB**. These complementary measures expose the perception/distortion tradeoff; neither a favorable spectrum metric nor an unfavorable waveform metric decides listener preference by itself. The reference is the original audience recording before the extra codec defect, not a clean concert source.

The four natural archive passages stayed close to their originals: raw-model onset-flux correlation was at least **0.999135**, weighted interchannel phase error at most **0.5205°**, and absolute width change at most **0.0497 dB**. That establishes limited preservation evidence, not that a listener prefers the altered recording. The source archive already uses higher-rate MP3s, and its room sound, tape defects and close audience noise are different problems from a new 64 kbps encoding.

`evidence/neural-apollo-results.json` preserves all measurements and the actual runtime. The local `audio-neural-probe/results/listening.html` package contains loudness-matched original/raw/25%-blend FLACs under randomized labels. Independently decoding those FLACs verified equal 441,000-frame lengths and less than 0.000001 LU level spread between conditions. Ratings remain empty. Apollo is still a research renderer; phone execution, app integration, real crowd semantics and subjective benefit are not established by these short tests.

### Apollo full-track validation

The source, checkpoint, script and inference configuration were frozen in `evidence/neural-apollo-freeze.json` before one complete development recording and two reserved midpoint passages. The complete 1996-12-06 *Sparkle* decoded to 217.208 seconds and 9,578,888 stereo frames. Local inference took **683.29 seconds (11 minutes 23 seconds, 3.146× real time)** and retained every frame. All output was finite, and the 20-second analysis windows showed zero estimated lag. This single full render is a bounded feasibility check, not a full-corpus neural evaluation.

Across those full-song windows, raw-model onset correlation was at least 0.99847 and weighted interchannel phase error at most 0.912°; the 25% blend gave at least 0.999838 and at most 0.237°. These small changes do not establish preference. Numerical chunk-boundary residual checks were also recorded; they are not a claim that seams are inaudible. The model input was scaled to reserve headroom, and comparison versions are independently loudness matched.

The fixed 1992-12-31 and 2025-07-26 reserved passages also completed, taking 77.98 and 61.35 seconds of local inference for their 14-second contexts. Raw-model onset correlation was at least 0.999013 and weighted phase error at most 0.313°; the 25% blend gave at least 0.9999298 and at most 0.081°. The complete full-track/held-out record is `evidence/neural-apollo-validation.json`, with separate source-integrity and listening-file checks. Decoded comparison lengths match exactly and level spread is below 0.0000003 LU. No parameter was retuned after the freeze.

**The file tail is less faithful than the full-track average.** Posthoc, analysis-only first/last-second checks found raw last-second waveform identity SNR of 21.86 dB versus 30.68 dB over the full song, onset correlation of 0.99063 and crest change of −0.765 dB. The 25% blend improved tail identity to 33.54 dB but still changed tail crest by −0.794 dB. `evidence/neural-apollo-edges.json` retains this finding. No parameters or output were changed to hide it. Future model integration needs explicit edge treatment and new validation; exact frame count alone is insufficient.

The local `audio-neural-probe/validation/listening.html` offers matched full-song and reserved-passage comparisons, with revealable Original/Apollo/25%-blend labels and the edge warning. Its existence is not a positive listening verdict. This model remains an experimental codec-restoration candidate and is not integrated with the app's saved-version producer.

### Mobile feasibility boundary

`export_probe.py` captured both the full waveform model and its real-valued neural backbone using `torch.export`, locally on CPU with the pinned checkpoint. `evidence/neural-export-feasibility.json` records the operator inventory and exact scope. A separate short nonzero-stimulus CPU parity check produced bit-identical waveform output for the whole model, but took 102 seconds including capture and execution. That combined probe reached its 120-second budget during the separate backbone check; `evidence/neural-export-parity.json` preserves the timeout. The subsequent capture-only probe confirmed both graphs again. Capturing a PyTorch graph and one short CPU parity result do not validate ExecuTorch lowering, an Android backend, mobile numerical parity, sustained memory use, thermal behavior, battery use or cancellation. This diagnostic timing is not a phone benchmark.

The captured waveform graph includes complex tensors, STFT/iSTFT and attention. The real-valued backbone avoids complex transforms, but moving those transforms outside the model would require matching Apollo's exact windowing, band layout and normalization. The current official XNNPACK support table does not list STFT/iSTFT or complex operators; this is an operator-coverage warning, not proof that every alternate backend or custom implementation is impossible. The official Android runtime also requires its library version to match the model export version. [XNNPACK operator support](https://github.com/pytorch/executorch/blob/main/docs/source/backends/xnnpack/op-support.csv), [official Android integration](https://github.com/pytorch/executorch/blob/main/docs/source/using-executorch-android.md).

A desktop-produced, source-bound enhanced-file import is a more concrete near-term route than promising phone execution, but the app does not yet implement that import. It would have to validate original-source identity, format, decoded frame count, model provenance and cancellation before atomic publication. The 66.5 MB checkpoint size is not a runtime-memory estimate. No model weights or upstream implementation have been added to the APK.

SonicMaster is a closer task match for room and mastering defects, but it is not a tested alternative here. Beyond the VAE access/license prerequisite, its inspected official inference pads final chunks without trimming the assembled output back to the source length, and clamps generated samples. Any future local experiment needs an audited exact-duration wrapper, unclipped-output diagnostics and musical-identity checks rather than assuming the upstream example meets this app's preservation contract.

## Listening and acceptance

The full-track harness extracts four comparison windows per recording, independently randomizes A/B labels, matches integrated loudness, applies common peak-safe attenuation, and writes FLAC files with a local browser player that switches at the same musical position. It records user ratings locally and permits ties. Rate overall preference, instrument/vocal naturalness, crowd presence, stereo image and transient artifacts on headphones. The numerical reports cannot supply these preferences. This is an informal blinded comparison, not a standards-compliant MUSHRA panel or a clean-reference restoration score.

The implementation's automated preservation gates are deliberately separated from listening preference. Passing them means it avoided the measured regressions within this corpus. It does not establish soundboard-like clarity, absence of all artifacts or superiority on arbitrary recordings. Peak estimates and instrumentation are not a certification. [ITU loudness/true-peak recommendation](https://www.itu.int/rec/R-REC-BS.1770), [ITU subjective evaluation recommendation](https://www.itu.int/rec/R-REC-BS.1534).

Before promoting a stronger treatment: collect actual blinded ratings, investigate recordings where this candidate abstains, test new untouched recordings, and obtain an appropriate local model/runtime with verified usage terms. Keep residual ambience and generated content independently auditable, and reject candidates that change musical identity even when a generic quality metric improves.

## Reproduction

Start with [REPRODUCING.md](REPRODUCING.md) for verified environment pins, acquisition and source-hash checks, scratch-directory requirements, frozen-script path limitations, and exact Android/classical/neural commands. Existing published evidence must not be overwritten by a fresh experiment.

Use an isolated Python environment. The full-track harness uses the parent directory's pinned `requirements.txt`, FFmpeg/FFprobe and Java 17 or newer. The optional WPE baseline additionally needs `nara_wpe==0.0.11`; it is not an Android dependency.

```sh
python acquire.py --help
python evaluate.py --help
python controlled_degradation.py --corpus /path/to/source-mp3s --output /path/to/controlled-results
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python model_comparison.py --corpus /path/to/source-mp3s --output /path/to/wpe-results
python neural_probe.py --help
python export_probe.py --source /path/to/pinned-Apollo --checkpoint /path/to/pytorch_model.bin --output /path/to/export-evidence.json
python classical_probe.py --help
python classical_full_track.py --help
```

The pinned manifests, compiled-source fingerprints, machine-readable measurements, development failures and final holdout results belong beside this method. Full audio stays in local artifact storage. No release, merge, upload or deployment is implied by this research record.
